# 两步式参与者选择弹窗

## Goal

让管理员在任务详情中添加参与者时，弹窗处于正确的视觉位置，并通过“选择人员 → 设备与设置”两步完成操作。第一步提供完整、可筛选的候选人列表，第二步再为已选人员确认设备及公共分配设置，减少同屏信息拥挤。

## Background and confirmed facts

- 用户截图显示桌面端“添加参与者”弹窗贴在视口左上方，而不是水平、垂直居中。
- 用户截图显示候选人列表底部出现半行被截断的视觉状态，列表边界与可滚动范围不清晰。
- 用户要求把“每人设备”从人员列表中拆出：第一步选择人员，第二步选择设备，并可在两步之间切换。
- 弹窗由原生 `<dialog>` 和共享 `.apple-dialog` 样式组成：`apps/admin-web/app/(console)/tasks/[taskPublicId]/add-task-participants.tsx:132-133`、`packages/ui/globals.css:168-179`。
- `.apple-dialog` 的桌面规则没有显式恢复居中所需的自动外边距；移动端在 `max-width: 639px` 下已明确使用底部弹层定位：`packages/ui/globals.css:265-277`。
- 当前候选列表只按姓名、参与者编号和地区做单一文本搜索，并固定为 `max-height: 25rem` 的内部滚动区：`apps/admin-web/app/(console)/tasks/[taskPublicId]/add-task-participants.tsx:70-75`、`apps/admin-web/app/(console)/tasks/[taskPublicId]/add-task-participants.tsx:157-168`。
- `participants` 数据已经包含可空的 `countryRegion`，本次筛选无需新增接口或服务端字段：`apps/admin-web/app/(console)/tasks/[taskPublicId]/add-task-participants.tsx:11-21`。
- 现有 E2E 已覆盖草稿任务打开弹窗、选择参与者和加入发布名单，可在同一流程补充布局与筛选断言：`tests/e2e/draft-task-participants.spec.ts:55-73`。

## Requirements

- R1. 在宽度大于 639 px 的桌面/平板视口中，“添加参与者”弹窗相对于当前视口水平、垂直居中；弹窗打开、选择人员和出现设备设置后都不能偏移到左上角。
- R2. 在宽度不超过 639 px 时继续使用现有底部弹层行为，不强制垂直居中。
- R3. 弹窗使用两个明确步骤：第一步“选择人员”，第二步“设备与设置”；第二步包含每人设备、任务版本或草稿说明、截止时间和分配备注。
- R4. 顶部步骤导航同时表达当前位置和完成状态；用户可以从第二步返回第一步，也可以在已选择至少一人后再次进入第二步。
- R5. 第一步未选择任何人员时禁止进入第二步，并给出清楚的按钮状态；第二步的最终提交规则和现有成功/失败反馈保持不变。
- R6. 往返切换步骤时保留文本搜索、地区选择、人员选择、公共设置和已选设备；筛选只改变当前可见候选，不清空已选择但暂时不可见的人员；若返回第一步主动取消某人，该人员及其设备值不再出现在第二步或提交负载中。
- R7. 第一步候选人列表使用明确的可滚动区域，滚动到末尾时最后一条记录及其圆角、状态和点击区域完整可见，不能被内容区或底部操作栏遮挡。
- R8. 第二步的每人设备列表可在内容区内滚动；关闭按钮、步骤导航、已选择人数和上一步/最终提交操作保持可达，不产生页面级滚动或横向溢出。
- R9. 每人设备继续允许“不指定设备”，并继续自动带入参与者的默认设备；分步不新增设备必选校验。
- R10. 在文本搜索旁增加紧凑的“地区”多选控件，选项从当前候选参与者的非空 `countryRegion` 去重并稳定排序生成，不新增网络请求。
- R11. 未选择地区时显示全部地区；选择多个地区时匹配其中任意一个地区（OR），再与姓名/编号搜索条件共同生效（AND）。
- R12. 地区控件清楚展示当前选择数量，支持逐项选择、取消和一键清空；仅键盘也能完成这些操作，并具有可见标签和焦点状态。
- R13. 地区为空的参与者在未启用地区筛选时正常显示；启用任一地区筛选后不匹配。
- R14. 本次只调整“添加参与者”弹窗的布局、步骤和客户端筛选，不改变参与者资格判断、设备分配默认值、提交接口、提交负载字段和移动端底部弹层语义。

## Out of scope

- 新增或修改参与者地区数据、管理 API、数据库字段或 Migration。
- 服务端筛选、分页或远程搜索。
- 修改发布名单、Assignment 创建、设备分配默认值或截止时间业务规则。
- 顺带重构其他管理弹窗；若共享样式修复会影响它们，需用现有弹窗做回归检查。

## Acceptance Criteria

- [x] AC1：在至少一个桌面视口打开“添加参与者”，弹窗中心点与视口中心点在水平和垂直方向的偏差均不超过 2 px。（R1）
- [x] AC2：在 390×844 视口打开弹窗，仍贴近底部并完整位于视口内，页面无横向溢出。（R2、R4）
- [x] AC3：弹窗打开后只显示第一步的搜索、地区筛选和候选人列表；未选择人员时不能进入第二步，选择至少一人后可进入。（R3、R5）
- [x] AC4：第二步显示已选人员的设备选择以及任务版本或草稿说明、截止时间和备注；可返回第一步，再回到第二步时已填值仍保留。（R3、R4、R6）
- [x] AC5：从第二步返回并取消某位参与者后，该人员不再出现在设备列表或最终提交中；其余选择保持不变。（R6）
- [x] AC6：候选人数超过可视区域时，第一步列表可滚动到最后一项，最后一项的边框、内容和选择区域完整可见；第二步设备较多时也可滚动到底，步骤与底部操作均可达。（R7、R8）
- [x] AC7：未指定设备仍可最终提交；有默认设备的参与者继续自动选中默认设备。（R9）
- [x] AC8：地区选项来自候选数据并去重；同时选择两个地区时，只显示属于任一所选地区的参与者，清空后恢复全部候选。（R10、R11、R13）
- [x] AC9：地区筛选与文本搜索组合生效，候选人数文案随结果更新；没有匹配项时继续显示现有空结果提示；切换筛选不会清空已选人员。（R6、R11）
- [x] AC10：地区多选和两步导航可通过键盘操作，均具有可访问名称、当前位置或状态以及可见焦点。（R4、R12）
- [x] AC11：现有草稿发布名单 E2E 仍能完成选择、下一步、设备设置、返回、最终提交、移除和再次加入；相关 lint、typecheck 与定向 E2E 通过。（R14）

## Technical notes

- 这是一个局部交互调整，PRD 足以约束实现，不需要单独的 `design.md` 或 `implement.md`。
- 优先修复造成桌面偏移的根因，并用移动端媒体查询保持现有底部弹层覆盖规则。
- 地区多选应呈现为紧凑的 select 式触发器和复选选项，不使用 macOS 需要 Command/Shift 辅助选择的原生多行 `<select multiple>`。
- 两步导航采用真正的按钮/步骤控件：第一步允许反复编辑选择，第二步才出现设备和最终提交按钮；第一步主按钮文案为“下一步：设备与设置”，第二步提供“上一步”和现有最终提交文案。
- 成功结果继续在当前弹窗中显示；成功后返回第一步刷新名单，不增加第三个完成步骤。
- 实施时补充 Playwright 的 bounding box、步骤往返、滚动末项和地区组合筛选断言；不依赖截图像素比较。
