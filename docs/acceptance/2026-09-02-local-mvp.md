## 上传、Metadata 与异常证据

`pnpm upload:test` 实际执行：

- FFmpeg 临时生成 5 秒、大小超过 6 MiB 的 1280×720 H.264 MP4，以 6 MiB TUS chunk 直传。
- 在第一个分片后 pause，使用 `findPreviousUploads()` 找到原资源并 resume；Complete 重放返回同一 VideoAsset。
- 验证所有视频请求命中 Storage/NAS Gateway 端口，未命中 Next.js `3000`。
- 服务端只做对象存在与大小对账；`50,000,001` bytes 返回 `413 FILE_TOO_LARGE`。
- Range metadata 保存 parser/version、attempt、Range 次数、读取字节与 allowlisted evidence；读取未超过 24 次 / 16 MiB。
- 手机 MP4 提取 MPEG-4、AVC、1280×720、约 5 秒和设备匹配。
- 临时生成 1024×512 equirectangular MP4，真实保存 `projection_type=equirectangular` 与 `is_360=true`。
- 同字节第二对象保留两个 active asset，只创建 Duplicate Candidate Review，不自动删除。
- 未上传对象触发 `storage_missing`；声明大小不一致触发 `size_mismatch`。
- 损坏 MP4 的 Transfer 保持 `verified`，Metadata 单独进入 `failed` 并创建 ReviewCase。

## 浏览器完整链路

Chromium 真实通过：

```text
Admin 登录
→ 创建 Participant
→ 生成邀请
→ Participant 接受并建立 Auth Session
→ Admin 登记无序列号 Device
→ 通过结构化表单创建 Task Draft 并发布不可变 v1
→ 创建 Assignment
→ Participant 移动端读取完整说明并确认 content hash
→ 创建 Recording Session
→ 展示并确认 Ed25519 Marker QR
→ 选择真实 MP4 并标记 Unable to Determine
→ TUS 直传、对象对账、Metadata
→ Admin 查看 Upload/Review 证据
→ Correct Session / Device
→ 新 MatchDecision supersede 旧 unmatched Decision
→ Assignment accepted、Session closed、AuditEvent 可见
```

Participant 会话访问 Admin API 返回 `403`。WebKit 另行完成真实文件选择、UploadIntent、Storage TUS、Complete；损坏内容的 Metadata `422` 不影响 Transfer `verified`。

Playwright 最终结果：`7 passed / 1 intentional skip`。被跳过的是限定只在 `webkit-smoke` project 运行的 WebKit 专用用例在 Chromium project 中的对应实例，不是未执行能力。
